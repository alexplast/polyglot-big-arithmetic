# План: улучшение воспроизводимости и удобства запуска

## Кратко
Сделать бенчмарки более воспроизводимыми и удобными: фиксировать среду и параметры, добавлять метаданные в результаты, улучшить CLI раннера, а CI запускать только вручную или по тегу. Обновить документацию подробно.

## Изменения в интерфейсах и выходных данных
- `tests/runner.py`:
  - Новые опции CLI: `--warmup`, `--no-plots`, `--no-report`, `--meta`.
  - В `results/` добавится `meta.json` с описанием окружения и параметров запуска.
  - В `RESULTS.md` появится раздел `Environment & Run Settings`.
- CI:
  - Workflow запускается только по `workflow_dispatch` и тегам вида `bench-*`.

## Детальные шаги

### 1. Метаданные окружения и параметров
Цель: фиксировать условия запуска для репродуктивности.

Изменения:
- В `tests/runner.py` добавить `collect_meta()`:
  - ОС/ядро: `uname -a`
  - CPU: `/proc/cpuinfo` (model name) или `lscpu`
  - RAM: `MemTotal` из `/proc/meminfo`
  - Версии: `gcc`, `g++`, `gfortran`, `rustc`, `go`, `javac`, `python3`, `node`
  - Git commit: `git rev-parse --short HEAD`
  - Timestamp и параметры запуска (`runs`, `warmup`, `bench`, размеры задач)
- Сохранять данные в `results/meta.json`.
- Добавить секцию `Environment & Run Settings` в `RESULTS.md`.

Примечание: без новых зависимостей, только `subprocess` и чтение `/proc`.

### 2. Прогрев и контроль параметров
Цель: снизить шум и сделать запуск стабильнее.

Изменения:
- В `tests/runner.py`:
  - Добавить `--warmup N` (по умолчанию `1`).
  - В `run_benchmark_cmd()` выполнять `N` прогонов без учета в статистике.
  - Добавить в CSV статистику разброса: `Min`, `Max`, `StdDev` (или отдельный `*_stats.csv`).
  - `--no-plots`: не запускать `tests/plot.py`.
  - `--no-report`: не перезаписывать `RESULTS.md`.

### 3. Детерминированные данные для сортировки
Цель: полностью повторяемый набор входных данных для Bubble Sort.

Изменения:
- В `tests/gen_data.py`:
  - Добавить `--seed` с дефолтом `1337`.
  - Логировать seed в `results/meta.json` и кратко в `RESULTS.md`.

### 4. CI только вручную и по тегу
Цель: убрать шум от автокоммитов на каждом push.

Изменения:
- В `.github/workflows/ci.yml`:
  - `on:` заменить на:
    - `workflow_dispatch` (inputs: `runs`, `bench`, `warmup`)
    - `push.tags: [ "bench-*" ]`
  - Оставить коммит результатов, но только для этих триггеров.
  - Для PR оставить только проверку корректности (`make docker_test`), без бенчмарков.

### 5. Подробная документация
Цель: минимизировать неявные знания для воспроизводимого запуска.

Изменения:
- В `README.md`:
  - Раздел `Reproducibility`: как читать `meta.json`, зачем `warmup/runs`, как использовать seed.
  - Раздел `CI policy`: ручной запуск и теги для обновления результатов.
  - Примеры команд:
    - `make docker_run`
    - `python3 tests/runner.py --bench matrix --runs 7 --warmup 2`

## Тесты и проверки
- `make docker_test`: проверка корректности.
- `make docker_run`: генерация `RESULTS.md`, CSV, plots, `meta.json`.
- Локально:
  - `python3 tests/runner.py --bench sort --runs 3 --warmup 1 --no-plots`
  - Проверить наличие и содержимое `results/meta.json`.

## Предположения и дефолты
- Целевая платформа: Linux/Docker.
- Методология: базовый контроль (прогрев и фиксация окружения).
- CI: обновление результатов только при `workflow_dispatch` и тегах `bench-*`.
- Новые внешние зависимости не добавляются.
